Core flow

  1. Sign in
  2. See ranked incidents
  3. Review causes with evidence, read next action, ask chat
  4. Confirm recovery (dialog) → review and save report
  5. Team lead checks results against baselines

Target: a new junior engineer completes steps 2 to 4 within 30 minutes of first use (NFR-10).

UX pillars and how the screens apply them

  • Evidence first: every cause lists the alerts, metrics or log lines behind it (REQ-006, NFR-12).
  • Low noise: one row per incident; severity shown by colour, symbol and word; filters and search on the list.
  • Local only: no external fonts, scripts or analytics; the page makes no network calls (REQ-014).
  • Plain language: next action written as numbered steps; no model jargon.
  • Honest uncertainty: confidence shown as number and bar, with a "low confidence" label below 50 %.

Type, spacing, shape

  • Font: Segoe UI / system sans; mono for log lines. Base 16 px; h1 24 px, h2 18 px.
  • Spacing scale: 4, 8, 12, 16, 24, 32 px. Minimum touch target 40 px.
  • Radius: 4, 8, 12 px. Motion: 150 ms, disabled when the user prefers reduced motion.

Accessibility and responsiveness (NFR-11)

  • Skip link, landmarks, one h1 per page, table captions and column scopes.
  • Keyboard access for every control; visible 3 px focus ring; dialog traps focus.
  • Status never shown by colour alone (symbol and text on severity and result badges).
  • Live regions for chat, toasts and banners.
  • Text, link, button and badge colour pairs were calculated at 6.5:1 or higher in light and dark themes (minimum 4.5:1 required). Borders and the confidence bar were not measured.
  • Layout adapts from 320 px to wide screens: sidebar becomes a top bar below 900 px.
